# Auto Connect Node Monitor — collector prototype

This module is the first isolated stage of the Yudou daily-node monitor.

## Rules

- Target date is China-local today minus two calendar days.
- The collector must find an article whose title contains that exact date.
- It never substitutes a neighboring date.
- It extracts only directly published HTTPS subscription URLs on `www.yudou89.shop` whose path contains the target date and whose suffix is `.txt`, `.yaml`, or `.yml`.
- It does not submit passwords, run page JavaScript, or bypass encrypted content.
- Subscription URLs are returned to the caller in memory only. CLI output intentionally prints metadata and subscription types, never the URLs.

## Local test

```bash
python -m unittest discover -s tests -v
```

## Manual collection

```bash
python collector.py --date 2026-11-04
```

The CLI prints a redacted summary. The collector probes each extracted subscription response and records a conservative node count. The API stores records in private Blob storage and exposes only metadata until an authenticated, type-specific import request. It does not import anything into the Android client yet. Those require the private storage/authenticated API stage and explicit user confirmation in the app.

## Security boundary for the next stage

- Never commit raw subscription URLs or fetched subscription bodies.
- Never put them in GitHub Actions logs or public artifacts.
- Store secrets in a private server-side store; authenticate app requests.
- Return only the selected pending record to the authenticated app.
- Keep collected subscriptions in a staging/pending area separate from active profiles.
- Require an explicit user action before import; back up active configuration and support rollback.

## Protected Vercel API

The Vercel project root is `tools/node-monitor`.

- `/api/cron`: daily Vercel Cron entry point. It requires `Authorization: Bearer <CRON_SECRET>`, runs the exact-date collector, and writes the complete pending record to a **private** Vercel Blob object.
- `/api/pending`: requires `Authorization: Bearer <NODE_MONITOR_API_TOKEN>`. Without a `type` query it returns metadata only and never returns subscription URLs. A type-specific request such as `?type=txt` returns that URL only for an authenticated explicit import request.
- `vercel.json`: runs at 00:00 UTC (08:00 Asia/Shanghai).

Required Vercel environment variables (never commit values):
- `CRON_SECRET`: long random secret used by Vercel Cron.
- `NODE_MONITOR_API_TOKEN`: separate long random bearer token for the Android client.
- `BLOB_READ_WRITE_TOKEN`: generated by a **Private** Vercel Blob store connected to this project.

Before deployment, create a Private Blob store and attach it to the project. Do not use a public Blob store. The Android app must keep its API token in Android Keystore-backed encrypted storage; it must not be hardcoded into the APK or repository.

The API intentionally keeps collection in a pending area. It has no endpoint that writes to the app's active proxy profiles. Import remains an explicit Android-side action.
